## 1. Authentication & Role-Based Access Control (RBAC)

The workspace relies on **Firebase Authentication** coupled with a custom role resolution layer. User access is partitioned strictly using custom middleware in `App.jsx`:

*   **Identity Provider**: Firebase Auth provides secure tokens (`firebaseUid`), while user credentials and profiles are mirrored in the database.
*   **Security Guards**: Direct access checks protect React routes on the client side using the `<ProtectedRoute>` component and on the API side using token validation middleware.
*   **Role Resolution Matrix**:
    *   **Admin/Super Admin/Manager**: Full read/write access to company operations, finance, HR directories, ID card creation, and marketing AI integrations.
    *   **Specialist/Employee/Developer/Editor**: Exclusive access to the employee self-service hub, timesheet management, leaf submittals, task board updates, and digital ID card passes.

## 4. Centralized Data Architecture

The platform operates a hybrid dual-database layer to maximize uptime and prevent issues caused by database connectivity drops:

```
                  ┌───────────────────────┐
                  │      Prisma Client    │
                  └───────────┬───────────┘
                              │
                    Query PostgreSQL DB?
                   /                    \
            (Online)                   (Offline / Failed)
             /                                    \
  ┌─────────▼────────┐                   ┌─────────▼─────────┐
  │   PostgreSQL     │                   │  Circuit Breaker  │
  │  (Schema Model)  │                   │     Triggered     │
  └──────────────────┘                   └─────────┬─────────┘
                                                   │
                                          ┌────────▼────────┐
                                          │ Firestore Vault │
                                          └────────┬────────┘
                                                   │
                                            (Firestore Timeout?)
                                           /                    \
                                       (No)                    (Yes)
                                       /                            \
                              ┌───────▼───────┐             ┌────────▼───────┐
                              │  Google Cloud │             │   Local JSON   │
                              │   Firestore   │             │  File Database │
                              └───────────────┘             └────────────────┘
```

### A. High Availability (HA) & Resiliency Features

*   **Postgres Circuit Breaker**: If PostgreSQL goes offline, the server sets a 1-minute failover flag. Subsequent database queries skip connection retry steps to load from the Firestore local vault immediately without lag.
*   **Firestore Operation Timeout**: Firestore requests are wrapped in a 3-second timeout. If the cloud database is slow or offline, it falls back to the local JSON file cache (`server/data/`) within 3 seconds.
*   **AI Request Timeout**: LLM completions are limited to an 8-second timeout. If the AI endpoint lags, the server switches to local structural templates instantly.
*   **Non-blocking Background Refresh**: The frontend page queries data concurrently using `Promise.all` and updates statistics in the background. Fresh updates do not block the active tab or freeze user input.

### B. Core Database Models (Prisma PostgreSQL)

*   **User (`users`)**: Handles user profiles, firebase authentication link (`firebase_uid`), and role bindings.
*   **Lead (`leads`)**: Stores companies discovered by the scraper, website URL, industry, scraped tech stack, contact email, and campaign status.
*   **LeadScore (`lead_scores`)**: Stores AI opportunity evaluation scores: budget, complexity, readiness, urgency, and the AI rationale log.
*   **Proposal (`proposals`)**: Generates custom proposals containing quote values, target service categories, and generated document texts.
*   **OutreachLog (`outreach_logs`)**: Records connection request dispatches via email, LinkedIn, or WhatsApp.
*   **Client (`clients`)**: Promotes converted leads to corporate clients.
*   **RetentionAlert (`retention_alerts`)**: Tracks client inactivity metrics and recommends engagement responses.

## 5. NEXA Agentic AI & Telegram Integration

The backend is connected to the **NEXA Agentic AI Administrator (NEXA AI Admin)**, which acts as the autonomous workspace director.

*   **NVIDIA Llama Endpoint**: Connects via `integrate.api.nvidia.com` using the `meta/llama-3.1-8b-instruct` model for low-latency responses (under 2 seconds).
*   **Telegram Bot Integration**: `@NexovTech_bot` is configured to run locally (when `TELEGRAM_POLLING=true` is set).
*   **Features available on Telegram**:
    1.  **Identity Verification**: Links Telegram ID to Firebase profile via `/start` wizard using a secure OTP email check or contact phone sharing.
    2.  **Mission Control (Admin Only)**: Dispatches tasks to employees (`/assign_task`) and triggers broadcast announcements (`/trigger_broadcast`).
    3.  **APK Distribution (Admin Only)**: Dispatches production binaries to connected specialists directly.
    4.  **Operational Dashboard**: Generates analytical summaries of leads, attendance index, leaves, and project health.

## 6. Startup & Local Development

### Prerequisites
*   Node.js (v18+)
*   PostgreSQL Database
*   Firebase Project Credentials

### Environment Setup (`server/.env`)
Create `server/.env` with the following variables:
```env
PORT=5006
DATABASE_URL="postgresql://<user>:<password>@localhost:5432/<db>?schema=public"
AI_BASE_URL="https://integrate.api.nvidia.com/v1"
AI_API_KEY="nvapi-..."
AI_MODEL="meta/llama-3.1-8b-instruct"
TELEGRAM_BOT_TOKEN="<token>"
TELEGRAM_POLLING=true
ADMIN_OVERRIDE_KEY="NEXOV-PRIME-2026"
```

### Launch Command
To run both client and server portals concurrently:
```bash
npm run dev
```
*   **Backend Admin API**: [http://localhost:5006](http://localhost:5006)
*   **Vite Client Portal**: [http://localhost:5173](http://localhost:5173) (or dynamic local port)
