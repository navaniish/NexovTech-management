# NEXA Growth Platform - Operations Guide

Welcome to the operations guide for the NEXA Growth Platform. This document outlines how to start, operate, and utilize the autonomous sales and business intelligence platform.

---

## 1. Quick Start Guide

To run the application, you must start both the backend Node.js server (listening on port `5006`) and the Vite React frontend client.

### Concurrent Startup (Recommended)
Open a terminal in the root directory and run:
```bash
npm run dev
```
This automatically manages and launches:
- **Backend API Server**: running at [http://localhost:5006](http://localhost:5006)
- **Frontend Client App**: running at [http://localhost:5173](http://localhost:5173) (or equivalent local Vite port)

### Independent Startup
If you prefer starting them in separate terminal windows:
- **Start Backend**:
  ```bash
  npm run server
  ```
- **Start Frontend**:
  ```bash
  npm run client
  ```

## 2. Core Functional Capabilities

Access the **NEXA Growth Platform** via the navigation panel of the client dashboard. It is divided into three key workspaces:

### A. CEO / Founder Dashboard
- **Real-time Metrics**: Displays totals for discovered leads, qualified hot leads, outreach campaigns sent, and conversion rates.
- **Revenue Analytics**: Visualizes growth and billing trends.
- **Executive AI Advisory**: Displays strategic, data-grounded business insights dynamically generated by the AI agent.

### B. Sales Hub
1. **Discovery Scraper Form**: Scrapes public directory niches (Healthcare, E-Commerce, etc.) for target businesses.
2. **Opportunities List**: Displays discovered companies, their scraped website domains, and identified tech stacks.
3. **Lead Qualification**: Click **Qualify** to evaluate budget suitability, urgency, readiness, and complexity.
4. **Outreach Channels**: Select a scored lead to draft connection requests for **LinkedIn**, hyper-personalized cold **Emails**, or **WhatsApp** business proposals.
5. **Proposal Creator**: Compiles customized technical proposals matching the target client's specific requirements and budget.

### C. Marketing AI
- Generates high-converting marketing updates tailored for social feeds (LinkedIn posts, Youtube scripts, Blog posts) based on project progress logs and achievements.

## 3. High Availability & Caching Features

To ensure the platform remains lightning-fast and responsive, the following architectural performance measures have been implemented:

*   **BI Recommendations Cache**: Recommendations generated by the LLM are cached. If the underlying metrics (leads, proposals, outreach) have not changed, subsequent dashboard loads are near-instant (`~40ms` instead of several minutes).
*   **Postgres Circuit Breaker**: If PostgreSQL goes offline, the server sets a 1-minute failover flag. Subsequent database queries skip the connection retry state to load from the Firestore local vault immediately without lag.
*   **Firestore Operation Timeout**: Firestore requests are wrapped in a 3-second timeout. If the cloud database is slow or offline, it falls back to the local JSON file cache (`server/data/`) within 3 seconds.
*   **AI Request Timeout**: LLM completions are limited to an 8-second timeout. If the AI endpoint lags, the server switches to local structural templates instantly.
*   **Non-blocking Background Refresh**: The frontend page queries data concurrently using `Promise.all` and updates statistics in the background. Fresh updates do not block the active tab or freeze user input.

## 4. Troubleshooting Reference

### Error: `net::ERR_CONNECTION_REFUSED`
*   **Reason**: The frontend client is trying to communicate with the backend on `http://localhost:5006`, but the backend server process is not running.
*   **Fix**: Go to the terminal and execute `npm run dev` (or `npm run server` inside the `server/` directory) to boot up the Node API service.

### Warning: `Can't reach database server at localhost:5432`
*   **Reason**: PostgreSQL server is offline.
*   **Behavior**: The platform will automatically fall back to the Firestore local vault.
*   **Fix**: Start your local PostgreSQL server instance, or verify that your `DATABASE_URL` in `server/.env` is configured correctly.
